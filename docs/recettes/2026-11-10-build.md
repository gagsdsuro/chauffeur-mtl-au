## Installation après validation

Transférer l'archive et son fichier `.sha256` vers `/tmp/` sur le serveur,
vérifier l'intégrité puis importer :

```bash
cd /tmp
sha256sum -c chauffeur-stm-2026-11-10-db9a6ca.tar.sha256
docker load -i chauffeur-stm-2026-11-10-db9a6ca.tar
```

Depuis le projet de production :

1. Conserver l'image précédente (`chauffeur-stm:livraison-2026-10-31`) pour
   le retour arrière ; sauvegarder `data/` et la configuration.
2. **Mettre à jour `data/reference/` sur l'hôte** (il vit dans le volume, pas
   dans l'image) : ajouter `periodes_stm_2027.json`,
   `points_de_releve_2026.json` et `points_de_releve_2027.json`, **retirer**
   l'ancien `points_de_releve.json`. Sans cela, les lieux de relève
   disparaissent sans message d'erreur.
3. Remplacer la section `build:` du service par :

   ```yaml
   image: chauffeur-stm:livraison-2026-11-10-db9a6ca
   ```

4. Conserver les volumes, UID/GID et paramètres de production, puis :

   ```bash
   docker compose up -d --no-build
   docker compose ps
   ```

5. Vérifier dans Ma journée qu'un lieu de relève s'affiche.

Régénérer explicitement les rapports v2 concernés depuis **Rapports →
Générer** : leur empreinte dépend des données, pas de la version du code.

Retour arrière : rétablir le tag de l'image précédente dans Compose,
restaurer l'ancien `data/reference/`, puis `docker compose up -d --no-build`.

**Aucun transfert ni déploiement en production effectué.**
